# Nimble Rivet

Двуязычный статический сайт студии для **https://nimble-rivet.github.io/**.

## Публикация на GitHub Pages

Сайт готов к публикации из корня ветки `main`, без Node.js, npm и стороннего сервера.

1. Отправьте содержимое репозитория в `Nimble-Rivet/nimble-rivet.github.io`.
2. Откройте **Settings → Pages**.
3. Выберите **Deploy from a branch → main → /(root) → Save**.
4. Дождитесь успешной задачи Pages во вкладке Actions. Адрес опубликованного сайта появится в Settings → Pages.

Все файлы находятся в корне репозитория: вложенные папки для публикации не нужны. Файл `.nojekyll` отключает обработку Jekyll. Все страницы уже сгенерированы. Для загрузки через GitHub **Add file → Upload files** перетащите все файлы сайта в корень репозитория: сам ZIP загружать вместо файлов не нужно.

## Редактирование

- Главные тексты и шаблоны страниц: `build.py`.
- Политики: `policy-*.md`.
- Оформление: `style.css`.
- Изображения и шрифт: в корне репозитория; происхождение и лицензия — `ASSETS.md`.

После изменений текстов или политик выполните:

```sh
python3 build.py
python3 check.py
```

Затем отправьте и исходники, и обновлённые HTML-файлы в `main`. CSS и изображения не требуют повторной генерации.

## Локальный просмотр

```sh
python3 -m http.server 8789 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8789/`. Используйте HTTP-сервер: адреса страниц и ресурсов рассчитаны на корень сайта, а не на `file://`.

## Содержимое

На сайте нет аналитики, cookies, внешних шрифтов, форм и клиентского JavaScript. Переключатель RU/EN ведёт на соответствующую версию текущей страницы. Контакт открывает почтовое приложение. Снимки экранов показывают демонстрационные данные.

Подтверждённых ссылок на опубликованные приложения пока нет. После публикации добавьте реальные ссылки магазинов и обновите сообщение о доступности в `build.py`. Не заменяйте их примерными адресами пакетов.

Для Retendly политика отдельно описывает системное резервирование Android и необязательное подключение Google Drive; сайт не обещает проверенную доступность облачного резервирования во всех сборках. Политики приложений не заменяют заполнение раздела Data safety и добавление ссылки внутри приложений.
